# Plugins and health

Plugins are managed by [lazy.nvim](https://github.com/folke/lazy.nvim), one spec file per area in `lua/plugins/`. The [plugin list](/reference/plugins) shows what's installed and when each one loads.

## Where things live

| Path                | What it is                                                   |
| ------------------- | ------------------------------------------------------------ |
| `init.lua`          | Sets `<leader>` and loads `lua/insomnia`                     |
| `lua/insomnia/`     | Options, global keymaps, theme restore, Pi detection         |
| `lua/insomnia/lsp/` | One file per language server                                 |
| `lua/plugins/*.lua` | Plugin specs (`ui`, `editor`, `git`, `lsp`, `terminal`, ...) |
| `lazy-lock.json`    | Pinned plugin versions. Commit it                            |
| `install.sh`        | Setup for Debian, Ubuntu and Raspberry Pi OS                 |
| `docs/`             | This site                                                    |

## Everyday tasks

| To                  | Do                                                      |
| ------------------- | ------------------------------------------------------- |
| Update plugins      | `:Lazy update`, try things out, commit `lazy-lock.json` |
| Roll back an update | `git checkout lazy-lock.json`, then `:Lazy restore`     |
| Add a plugin        | Add a spec to a file in `lua/plugins/` and restart      |
| Remove a plugin     | Delete its spec, restart, then `:Lazy clean`            |
| See startup cost    | `:Lazy profile`                                         |

Inside `:Lazy`: `U` update, `S` sync, `X` clean, `R` restore, `P` profile, `?` help.

A minimal spec that loads only when needed. Give every key a `desc`: which-key and these docs read it.

```lua
-- lua/plugins/example.lua
return {
  {
    "author/plugin.nvim",
    keys = { { "<leader>x", "<cmd>Cmd<CR>", desc = "Do the thing" } },
    opts = {}, -- passed to require("plugin").setup(opts)
  },
}
```

## Treesitter

Parsers are listed in `lua/plugins/treesitter.lua`; only missing ones are built on startup. Use `:TSInstall <lang>`, `:TSUpdate` and `:InspectTree`.

If you see `Error during tree-sitter build … ENOENT`, check `tree-sitter --version`. If the CLI is fine, the download probably failed: retry with `:TSInstall! <lang>`.

## Health checks

| Command                        | Checks                                  |
| ------------------------------ | --------------------------------------- |
| `:checkhealth lazy`            | lazy.nvim                               |
| `:checkhealth nvim-treesitter` | tree-sitter CLI, compiler and parsers   |
| `:checkhealth vim.lsp`         | Servers attached to the buffer          |
| `:checkhealth blink.cmp`       | Completion and its fuzzy matcher binary |
| `:ConformInfo`                 | Formatters for this file, and their log |
| `:Mason`                       | Installed servers and tools             |

## How these docs are built

The pages under **Reference** are generated by `docs/scripts/generate.lua`. It starts Neovim headless with this config and reads the keymaps (every `desc`), plugin specs, `lazy-lock.json`, language servers, formatters, linters, options and themes. A GitHub Action runs it and deploys the site on every push to `main`, so changing the config updates the docs. The guide pages are written by hand.

To preview locally:

```shell
cd ~/.config/nvim/docs
npm install
npm run docs:dev
```
